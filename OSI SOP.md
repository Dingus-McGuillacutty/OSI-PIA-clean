# SOP-001: Documentation Breaks

## Purpose

To preserve architectural decisions, methodology, and implementation details before beginning the next phase of development.

Documentation is considered part of development, not a task performed after development.

---

## Trigger Conditions

A documentation break should occur whenever one or more of the following occurs:

- A new architectural pattern emerges.
- An ontology changes.
- A methodology changes.
- A validation process is created or modified.
- A pipeline stage is added.
- A repository structure changes.
- An ADR is created.
- A development sprint concludes.
- A major milestone is reached.

---

## Documentation Checklist

Before continuing development:

- [ ] Update README files
- [ ] Update architecture documentation
- [ ] Record new ADRs
- [ ] Update methodology documents
- [ ] Update maturity model
- [ ] Update repository structure if needed
- [ ] Document validation changes
- [ ] Record outstanding questions
- [ ] Create next sprint backlog

---

## Definition of Done

A development sprint is not considered complete until its documentation has been updated.

Documentation is a project artifact equal in importance to source code.
