# OSI Documentation

This directory is the organized documentation system for Organizational Systems Intelligence (OSI) and Professional Identity Architecture (PIA).

## Documentation map

| Area | Purpose |
|---|---|
| `architecture/` | Stable system design and contracts |
| `components/` | Reference manuals for implemented components |
| `decisions/` | Architecture Decision Records and decision rationale |
| [`history/`](history/README.md) | Milestones and architectural evolution |
| [`evidence/`](evidence/README.md) | Synthetic demonstrations, controlled validation records, and research examples |
| [`runbooks/DEVELOPMENT_WORKTREE_CHECKPOINT.md`](runbooks/DEVELOPMENT_WORKTREE_CHECKPOINT.md) | Worktree, verification, commit, and clean-release checkpoint |
| `active-research/` | Hypotheses and exploratory work not yet promoted into architecture |
| `principles/` | Enduring engineering and ethical commitments |
| `GLOSSARY.md` | Reader-oriented terminology guide |
| `FOR_HUMANS.md` | Human orientation to the repository's knowledge structure |
| `FOR_MACHINES.md` | Machine operating assumptions and epistemic boundaries |
| `../foundation/CANONICAL_TERMINOLOGY.md` | Authoritative formal definitions |
| `history/PROJECT_VOCABULARY.md` | Cultural and historical project language |
| `PROJECT_STATUS.md` | Current implementation, authorization, and next-decision snapshot |
| `PLATFORM_OVERVIEW.md` | Ten-minute technical orientation to the platform |

## Documentation states

Research documents describe possibilities.

Architecture documents describe stable design.

Component documents describe implemented behavior.

ADRs preserve decision rationale.

History records when important transitions occurred.

Principles define the boundaries within which all of the above should evolve.
